# Silent Voice — ML workspace

This folder holds everything related to training and serving the sign-recognition models. It is **decoupled from the web app**: the FastAPI backend only reads `models/*.pt` at boot. Nothing here needs to run inside the Emergent pod.

```
ml/
├── data/
│   ├── include/        ← drop the INCLUDE dataset extraction here (raw MP4s)
│   ├── custom/         ← your 15–20 self-recorded phrase clips
│   └── processed/      ← .npy landmark tensors (auto-generated by preprocess.py)
├── models/             ← trained .pt weights land here (auto-loaded by backend)
├── scripts/
│   ├── dataset.py           # shared PyTorch Dataset for landmark tensors
│   ├── models.py            # BiLSTM + Transformer definitions
│   ├── preprocess.py        # MediaPipe → .npy landmark extraction
│   ├── train_bilstm.py      # trains models/bilstm.pt
│   ├── train_transformer.py # trains models/transformer.pt
│   └── evaluate.py          # side-by-side val/test metrics for both models
├── logs/               ← training logs, confusion matrices, tensorboard runs
└── requirements.txt    ← Python deps for training (heavy: torch, mediapipe)
```

## The dataset is huge. Here's how to survive it.

The full INCLUDE download is ~57 GB compressed and ~120 GB extracted. You almost certainly don't need all of it. Pick the path that matches your constraints:

| Path | Peak disk | Permanent disk | Classes | Recommended for |
|---|---|---|---|---|
| Full INCLUDE, keep videos | ~120 GB | ~120 GB | 263 | Only if you have a beefy workstation |
| Full INCLUDE, `--delete-after` | ~120 GB | ~230 MB | 263 | Colab / Kaggle sessions (temp storage plenty) |
| **INCLUDE-50** (official subset) | ~15 GB | ~50 MB | 50 | **Recommended for laptops** |
| Class-whitelist (~90 classes) | ~30 GB | ~150 MB | 90 | Best coverage of the app's vocab |

**Shrinking tricks the preprocessing script supports:**
- `--classes classes_locked.txt` — only extract landmarks for whitelisted classes (a curated `classes_locked.txt` covering the Everyday + Medical + Classroom packs is already in `scripts/`)
- `--max-per-class 6` — cap the number of takes per class (fewer signers, faster training)
- `--delete-after` — delete the raw video the moment its `.npy` tensor is written safely. Peak disk stays low.

## After you download the datasets — do these steps in order

### 0. Pick a place to run it

- **Laptop with SSD:** fine for INCLUDE-50 or a whitelist. Aim to keep 40 GB free.
- **Colab / Kaggle:** ideal. ~100 GB ephemeral disk per session. Do preprocessing there, download only the ~150 MB `.npy` tensors home.
- **Any GPU box:** identical steps, just faster training.

### 1. Place the raw data

- **INCLUDE (IIT Bombay)** — download from https://zenodo.org/record/4010759. If you only want INCLUDE-50, grab the smaller archive from the same Zenodo record. Extract into:
  ```
  data/include/Adjectives/1. above/MVI_9542.MOV
  data/include/Nouns/1. book/MVI_5001.MOV
  ...
  ```
- **Self-recorded phrase clips** (~15 minutes total effort): 720p, front-lit, plain backdrop, one label per subfolder:
  ```
  data/custom/hello/take_01.mp4
  data/custom/i_love_you/take_01.mp4
  ...
  ```

### 2. Install training deps (on Colab / your GPU box — NOT in the web-app pod)

```bash
cd /app/ml
pip install -r requirements-training.txt
```

### 3. Extract landmarks (recommended low-footprint invocation)

```bash
# 30 GB peak, 150 MB permanent — best trade-off for a student project
python scripts/preprocess.py \
    --videos data/include \
    --out data/processed/include \
    --classes scripts/classes_locked.txt \
    --max-per-class 8 \
    --delete-after

python scripts/preprocess.py \
    --videos data/custom \
    --out data/processed/custom
```

`--delete-after` is safe — a `.npy` tensor is only written once MediaPipe successfully processes the whole clip. Nothing is deleted before that.

### 4. Train both models

```bash
python scripts/train_bilstm.py       --epochs 40 --batch 32
python scripts/train_transformer.py  --epochs 40 --batch 32
```

Best checkpoints save to `models/bilstm.pt` and `models/transformer.pt`.

### 5. Side-by-side evaluation

```bash
python scripts/evaluate.py
```

### 6. Copy artifacts to the web app

```bash
cp models/bilstm.pt models/transformer.pt models/label_map.json models/preproc_stats.json \
   /app/backend/models/
sudo supervisorctl restart backend
```

### 7. (Optional) Record MP4 sign clips for the reverse-mode player

Upload MP4 + WebM to object storage, then update `sign_clips` documents in MongoDB with the `videoUrl` field. The `SignClipPlayer` component swaps skeleton → real video automatically.

## Should I use ISL-CSLTR instead?

Short answer: **no, not alone.** ISL-CSLTR is a *continuous* sign-language dataset (sentences, ~700 samples, ~9 GB) built for sequence-to-sequence translation with CTC loss. Our classifiers work on *isolated* signs. Different problem shape, worse per-class sample count, more complex training. Feel free to add ISL-CSLTR clips *on top of* INCLUDE-50 later for signer variance — but it's not a replacement.
